## 2.1 实施前的源码核实（本机 UE 5.4）

### 插件名是 `GameplayAbilities`，不是 `GameplayAbilitiesPlugin`

实测 `Engine/Plugins/Runtime/GameplayAbilities/GameplayAbilities.uplugin`。
注意与 `ChaosVehiclesPlugin` 命名习惯不同 —— Chaos 那个带 Plugin 后缀，GAS 不带。写错会导致 Editor 启动时报"插件未找到"。

### GAS 插件自动连带启用 3 个插件

`.uplugin` 的 `Plugins[]` 声明了依赖：`GameplayTagsEditor` / `Niagara` / `DataRegistry`，均 `Enabled: true`。
→ `.uproject` 里**只需写 `GameplayAbilities` 一条**，不用手动加这三个。

### GameplayTags / GameplayTasks 是引擎核心模块，非插件

实测两者都在 `Engine/Source/Runtime/` 下（不在 `Engine/Plugins/`）：
- `Engine/Source/Runtime/GameplayTags`
- `Engine/Source/Runtime/GameplayTasks`

→ 它们只需写进 `Build.cs` 的依赖数组，**不需要在 `.uproject` 的 `Plugins[]` 里启用**。
这是常见混淆点：三个模块名都以 Gameplay 开头，但只有 GameplayAbilities 是插件。

### GAS 模块 LoadingPhase 是 PreDefault

`GameplayAbilities` 模块 `"LoadingPhase": "PreDefault"`，早于项目模块（Default）加载，所以项目里可以安全引用其类型，无需调整自己模块的 LoadingPhase。

### Config 无需预先配置

`Config/` 当前只有 4 个默认 ini，无 GameplayTags 相关配置 —— 这是正常的。
首次在 Editor 里创建 Tag 时会自动生成 `Config/DefaultGameplayTags.ini`。不用手动建。

## 2.2 实施前的源码核实（UE 5.4）

### 引擎自带示例不可作为模板

`AbilitySystemTestAttributeSet.h` 是引擎内部单元测试用，写法是**裸 `float` + `mutable`**，且源码注释明确写了 *"Mutable is not required and should never be used on normal attribute sets"*。
→ 不要参考它。生产写法必须用 `FGameplayAttributeData`。引擎内没有生产级 AttributeSet 范例（Lyra 才有），所以参考 tranek 文档。

### `UAttributeSet` 基类用 `GENERATED_UCLASS_BODY()`

实测 `AttributeSet.h:180-182`。子类用 `GENERATED_BODY()` 即可（现代写法）。

### `GAMEPLAYATTRIBUTE_REPNOTIFY` 的真正作用（`AttributeSet.h:401-405`）

宏体调用 `SetBaseAttributeValueFromReplication(Attribute, PropertyName, OldValue)`。
关键：它**不是简单赋值**，而是把 OldValue 一起传给 ASC，让 ASC 能正确处理**客户端预测回滚** —— 客户端预测改了属性，服务器复制回真值时，ASC 需要旧值才能算出预测偏差。
自己在 `OnRep_Xxx` 里直接赋值 = 破坏预测系统，单机看不出问题，联机会属性抖动。

### AttributeSet 钩子的精确分工（源码注释原文）

- `PreAttributeChange` (:215)：*"meant to enforce things like Health = Clamp(Health, 0, MaxHealth) and NOT things like trigger this extra thing if damage is applied"* → **只做钳制，不做业务逻辑**
- `PreAttributeBaseChange` (:226)：*"should enforce clamping (presuming you wish to clamp the base value along with the final value in PreAttributeChange)"* + *"should NOT invoke gameplay related events"* → 钳制 BaseValue，同样禁业务逻辑。注意签名是 `const`
- `PostGameplayEffectExecute` (:201)：*"only called during an 'execute'... It is not called during an application of a GameplayEffect, such as a 5 second +10 movement speed buff"* → **只有 Instant/Periodic GE 触发，Duration/Infinite GE 不触发**。业务反应逻辑放这里
- `PostAttributeChange` (:218)：任何修改后都调用

**重要推论**：Boost 用 Infinite GE 改 MaxSpeed → **不会**触发 `PostGameplayEffectExecute`。所以"MaxSpeed 变化 → 同步给 Movement"这个桥必须走 `GetGameplayAttributeValueChangeDelegate`，不能指望 PostGameplayEffectExecute。
