## 🔴 packed-refs 坑复发 —— 找到真根因并彻底修掉

08-30 那次只写 loose ref，**修法不彻底**。本次 push 后问题复发：
push 明确报告 `4ab0bff..a9d54bc main -> main` 成功，
但 `git rev-parse origin/main` 又读回远古的 `e693512`，`git status` 误报 ahead 10。

### 排查过程（排除了几个错误假设）

| 假设 | 验证结果 |
|---|---|
| `.git` 或 packed-refs 不可写 | ❌ 排除，两者都可写 |
| 用了 reftable 后端导致旧文件失效 | ❌ 排除，`extensions.refstorage` 未设置、无 `.git/reftable` |
| OneDrive 同步回滚文件 | ❌ 排除，`$OneDrive` 未设置，项目不在同步范围 |
| 自定义 hook 干扰 | ❌ 排除，四个 hook（post-checkout/commit/merge、pre-push）是 Git LFS 标准安装 |
| 写入根本不生效 | ❌ 排除，实测写 loose ref 立刻能读回 |

**真根因**：`.git/packed-refs` 这个文件**长期没被任何 git 操作重写过** ——
mtime 一直停在 `Apr 20 21:43`，期间所有 fetch/push 都没能更新它。
而 08-30 手工写的 loose ref 在后续 push 过程中被清理掉，
陈旧的 packed-refs 记录重新浮出水面 → 问题复发。

### 彻底修法（已验证）

```bash
REAL=$(git ls-remote origin refs/heads/main | cut -f1)
mkdir -p .git/refs/remotes/origin
printf '%s\n' "$REAL" > .git/refs/remotes/origin/main   # 临时纠正
git pack-refs --all                                      # 关键一步
```

`git pack-refs --all` 成功重写了 packed-refs（mtime 终于变成 `2026-09-06 00:10:38`），
陈旧记录被彻底替换。之后 `fetch` 幂等、三值（HEAD / origin/main / ls-remote）完全一致。

**教训**：只写 loose ref 是治症状；必须跟一次 `git pack-refs --all` 才是治根。
已把正确修法更新进 MEMORY.md（替换掉 08-30 那个不彻底的版本）。
