## 从 .codebuddy 迁移过来的 Q&A（原 06-09 记录）

### Q&A 1: AddMovementInput 与 UFloatingPawnMovement 的关系

用户问：为什么构造函数中添加了 UFloatingPawnMovement，移动时却用 AddMovementInput？

答：AddMovementInput 是 APawn 的方法，它只是把移动意图累积到 ControlInputVector，真正的移动由 UFloatingPawnMovement::TickComponent 读取该向量后按 Acceleration/MaxSpeed/Deceleration 计算并执行。两者是生产者-消费者关系。AddActorWorldRotation 则直接改变 Actor 朝向，不经过 Movement 组件。

### Q&A 2: ControlInputVector 的归属与类间关系

用户问：ControlInputVector 属于哪个类？在几个重要类中的关系是什么？

答：ControlInputVector 是 APawn 的 protected 成员 (FVector)，代表"本帧累积的移动意图"。

**数据流**：
1. PlayerController 触发输入
2. APawn::AddMovementInput 写入 ControlInputVector
3. UFloatingPawnMovement::TickComponent 调用 ConsumeMovementInputVector() 读取并清零
4. 按 Acceleration/MaxSpeed/Deceleration 计算 Velocity
5. SafeMoveUpdatedComponent 执行位移

**设计目的**：解耦输入与移动执行，支持输入累积、平滑加减速、碰撞检测和网络同步。

### 踩坑：packed-refs 写入被静默拦截（重要，可能复发）

**现象**：`git fetch` 报 `e693512..4ab0bff main -> origin/main` 成功，但 `git rev-parse origin/main` 仍返回旧值 `e693512`。连做两次 fetch + 一次 `git update-ref` 均"成功但无效"，磁盘 `.git/packed-refs` 内容完全没变、`.git/refs/remotes/origin/` 目录也没生成。

**危害**：`git diff HEAD origin/main` 实际在跟 4 个月前的远古提交比对，输出了 **13 个文件几乎全部 D、-372 行**的假 diff，看着就像"远程要删库"。当时已停手改为诊断，没有贸然 pull/reset —— 这个假象足以骗人做出错误的 `reset --hard`。

**根因**：ref 只存在于 `packed-refs`（无 loose ref 覆盖），而 packed-refs 写入被静默拦截（Windows 上 Editor / VS / 杀软持有 `.git` 句柄时会出现，exit code 仍为 0）。

**修复**：手动写 loose ref（优先级高于 packed-refs），绕过 packed-refs 写入路径：
```bash
mkdir -p .git/refs/remotes/origin
printf '<40位完整sha>\n' > .git/refs/remotes/origin/main
```
写完 `git rev-parse origin/main` 立刻正确，`git status` 从误报 `ahead 8` 恢复为干净。

**下次判据**：只要出现「fetch 报成功 + rev-parse 读旧值」，先 `grep origin .git/packed-refs` 和 `cat .git/refs/remotes/origin/main` 对磁盘取证，**不要相信 diff 结果**。

### 校验

`git status` = `## main...origin/main`（无 ahead/behind）；`git lfs ls-files` 7 个资产全部 `*`（已实体化，非指针）；`git fetch` 幂等无新内容。

### 3. `DEV_PLAN` 2.2 的 `CurrentSpeed` 是设计错误（重要）

`CurrentSpeed` 不该做 GameplayAttribute。Attribute 的意义是「被 GE 修改 + 自动复制 + 带 Pre/PostModify 钩子」，而当前速度是 `UFloatingPawnMovement::Velocity` 的派生只读值，没有任何 GE 会改它。放进 AttributeSet = 每帧手动同步、白占复制带宽。

正确划分：
- **是 Attribute**：`Stamina` / `MaxStamina` / `StaminaRegenRate` / `MaxSpeed`（GA_Boost 要改它）
- **不是 Attribute**：`CurrentSpeed` —— HUD 直接读 `Movement->Velocity.Size()`

### 待用户决策

### 关键集成点（AttributeSet 与 Movement 的桥）

`MaxSpeed` 变成 Attribute 后，AttributeSet 只是数据容器，**不会自动作用于移动组件**。必须监听 `GetGameplayAttributeValueChangeDelegate(...)` 把值推给 `Movement->MaxSpeed`。这是 GAS 新手最容易漏的一环。

### 另一个已知隐患（Phase 4 会爆）

`HandleSteering` 在输入回调里调 `GetWorld()->GetDeltaSeconds()` 做旋转积分。输入回调每帧触发次数不保证为 1（按住时 Triggered 可能多次、松开还有 Completed），转向速度会随触发次数漂移。正确做法是回调只存 `SteeringInput`，在 `Tick` 里统一积分。当前单机手感已调好没暴露，但网络预测阶段必炸。Phase 2 不动，留到 Phase 4 或用户想优化手感时处理。
