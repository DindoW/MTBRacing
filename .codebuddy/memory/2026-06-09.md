## Q&A: AddMovementInput 与 UFloatingPawnMovement 的关系

用户问：为什么构造函数中添加了 UFloatingPawnMovement，移动时却用 AddMovementInput？

答：AddMovementInput 是 APawn 的方法，它只是把移动意图累积到 ControlInputVector，真正的移动由 UFloatingPawnMovement::TickComponent 读取该向量后按 Acceleration/MaxSpeed/Deceleration 计算并执行。两者是生产者-消费者关系。AddActorWorldRotation 则直接改变 Actor 朝向，不经过 Movement 组件。

## Q&A: ControlInputVector 的归属与类间关系

用户问：ControlInputVector 属于哪个类？在几个重要类中的关系是什么？

答：ControlInputVector 是 APawn 的 protected 成员 (FVector)，代表"本帧累积的移动意图"。数据流：PlayerController 触发输入 → APawn::AddMovementInput 写入 ControlInputVector → UFloatingPawnMovement::TickComponent 调用 ConsumeMovementInputVector() 读取并清零 → 按 Acceleration/MaxSpeed/Deceleration 计算 Velocity → SafeMoveUpdatedComponent 执行位移。设计目的：解耦输入与移动执行，支持输入累积、平滑加减速、碰撞检测和网络同步。
